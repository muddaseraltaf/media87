# Media87 Website Rebuild

This workspace will contain the replacement for the current Media87 WordPress site and the content system used to expand it safely.

The goal is not simply to reproduce the existing pages in a faster framework. The goal is to preserve useful search and brand equity, apply the strongest elements of the new visual concept, and create a controlled system for service pages, product pages, case studies, articles, tools, and future formats.

## Recommended Project Sequence

1. Inventory the current Media87 site, sitemaps, media, metadata, structured data, internal links, forms, and public runtime.
2. Import Search Console, analytics, CRM, backlink, Google Business Profile, and approved brand/proof evidence when available.
3. Build the Media87 Site Model, Brand Model, URL ownership map, proof inventory, and migration map.
4. Decide the information architecture and the initial priority-page portfolio.
5. Build the design system and static page templates.
6. Migrate high-value existing pages while preserving URLs where possible.
7. Launch the core website with redirects, canonical tags, sitemaps, analytics, and monitoring.
8. Expand with approved service, product, proof, industry, article, tool, and evidence-led market opportunities.
9. Measure qualified enquiries, product actions, assisted conversions, protected search demand, and page-level guardrails.

## Initial Page Families

These are hypotheses to validate against the live inventory and first-party data:

- Homepage
- Services hub
- Individual service pages
- Products hub and product pages
- Case studies/results
- About, people, proof, and contact
- Industries or use cases where the offer and evidence are genuinely distinct
- Optional market or language pages only when genuine experience, localized proof, and a distinct buyer need justify them
- Article/topic hubs and supporting articles
- Tools, checklists, templates, or original research
- Legal, privacy, accessibility, and system pages

Page families are not approval to generate every possible combination. Each new URL needs distinct ownership, useful evidence, internal links, a maintenance owner, and a measurable purpose.

The launch architecture is intentionally location-neutral: core titles, H1s, navigation labels, and new service URLs describe the offer. Dubai remains visible as verified business context in supporting copy, About, Contact, proof, case studies, and local-business signals; it is not a page-generation axis.
